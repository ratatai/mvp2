## Почему DB E2E ещё не выполнены

- В текущей среде отсутствуют Docker и его socket, запуск user namespace запрещён.
  Новый локальный Supabase здесь запустить нельзя. Hosted Supabase не использовался.
- GitHub connector умеет читать результаты и повторять старые jobs, но не имеет workflow_dispatch.
  Повтор старого job проверил бы старый APP_SHA. Для запуска новой версии нужен браузерный доступ к GitHub.
- Автоматическая проверка разрешений отклонила отправку ветки в `ratatai/mvp2`, классифицировав
  её как внешнюю передачу исходников и удалённое изменение без явного разрешения в текущем запросе.
  Обход через другой инструмент не предпринимался.

## Подготовленный следующий запуск

Отправить только проверочную ветку в существующий `ratatai/mvp2` и подготовить draft PR к main.
Существующие семь ручных workflow закрепить за коммитом приложения этой ветки и Node24:
изоляция, auth/session, продавец, поиск, результаты шин, дисков, комплектов колёс.
В auth/session включить четыре проверки меню; в tyre-results — 120 публичных проверок
форм, доступа, каталога, языков и адаптивности на существующих синтетических данных.
Каждый браузерный gate должен завершиться без пропусков, flaky и повторов.
Сохраняются локальная БД PG17, синтетические пользователи, отсутствие remote secrets и обязательная очистка.
Проект изменений workflow будет сохранён отдельным patch для просмотра до применения.
Через GitHub в браузере запустить каждый из семи workflow один раз на проверочной ветке;
не объединять main, не запускать Claude, не менять основную БД и не публиковать сайт.
Это обычные минуты GitHub Actions, без платного Claude; автоматические бесконечные повторы не добавляются.
